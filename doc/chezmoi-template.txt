1. INTRODUCTION                                 *chezmoi-template-introduction*

chezmoi-template.nvim makes Neovim understand chezmoi (https://chezmoi.io)
source files, so you edit them natively instead of going through
`chezmoi edit`:

- *.tmpl buffers are 'filetype' gotmpl with the deployed target language
  treesitter-injected (a dot_zshrc.tmpl highlights as Go template + zsh).
- A conform.nvim formatter formats templates with the TARGET filetype's
  formatter by masking Go-template spans and restoring them afterwards.
  Lines with no valid placeholder form (a template glued to a bare word, a
  control-flow pair wrapping an entry) are masked whole and come back
  untouched, so they never block formatting the rest of the file.
- mini.icons lookups resolve source names (private_dot_config/...) to their
  deployed targets.
- Optional transparent decrypt/encrypt of chezmoi-managed encrypted files
  (*.age, *.asc).
- Template errors surface as |vim.diagnostic| entries on write.
- User commands for apply/diff/preview/source-jumping, and |gf| on a
  `{{ template "…" }}` name opens the file in `.chezmoitemplates/`.

Everything degrades gracefully when the `chezmoi` binary is missing.

2. SETUP                                               *chezmoi-template-setup*

The plugin bootstraps itself with defaults; a setup() call is only needed to
change options. With lazy.nvim: >lua

  {
    "dpezto/chezmoi-template.nvim",
    lazy = false, -- keep false; the plugin lazy-loads itself internally
    opts = {},
  }
<
`lazy = false`, but startup stays cheap: only filetype detection and light
triggers register up front; the heavy setup() is deferred until the first
managed file opens or a :Chezmoi* command runs. Don't set ft/cmd — the internal
bootstrap handles lazy-loading, and its filetype registration must run at
startup.

Managed files that are not templates (most of a source directory) are
recognized by source-dir membership, so the first buffer of a session resolves
the source dir with one `chezmoi source-path`, cached from then on. Setting the
source_dir option skips that lookup.

Without a plugin spec, options can also be set via >lua

  vim.g.chezmoi_template = { encryption = { enabled = true } }
<
before the plugin loads.

3. OPTIONS                                           *chezmoi-template-options*

Defaults: >lua

  require("chezmoi-template").setup({
    source_dir = nil,            -- nil = auto via `chezmoi source-path`
    inject = {
      enabled = true,            -- treesitter target-language injection
      exclude = {},              -- lua patterns (matched on the normalized
                                 -- "/" path) to leave as plain gotmpl
    },
    format = {
      enabled = true,            -- conform formatter registration
      indent_directives = true,  -- depth-pad column-0 {{- directive blocks
    },
    icons = { enabled = true },  -- mini.icons resolution
    apply = {
      on_save = true,            -- chezmoi apply <target> after writing;
                                 -- chezmoi's own source state (see below)
                                 -- reports warnings instead
      notify = true,             -- notify on successful applies
      force = false,             -- pass --force (skip chezmoi's prompt on
                                 -- externally-modified targets)
    },
    preview = {
      live = true,               -- re-render as you type (false = on write)
      debounce = 150,            -- ms of idle before a live re-render
      slow_ms = 500,             -- renders slower than this pause live
                                 -- preview to on-write; 0 disables
      split = "vertical",        -- "vertical"|"horizontal" preview window
    },
    notify_on_open = false,      -- notify when opening a managed source file
    redirect = false,            -- deployed file open -> jump to source
    diagnostics = { enabled = true },
    completion = {
      -- hide values of matching data keys in completion docs
      mask = { "secret", "token", "passw", "key", "api" },
    },
    picker = {
      backend = nil,             -- "snacks"|"telescope"|"fzf-lua"|"mini"|
                                 -- "select"; nil = auto-detect
      display = "target",        -- entry labels: "target" (.zshrc) or
                                 -- "source" (dot_zshrc.tmpl)
      exclude = {},              -- lua patterns (vs the source-relative
                                 -- path) hidden on top of the built-in
                                 -- internals list; false = show everything
    },
    keymaps = {
      enabled = false,           -- buffer-local bindings in source buffers
      prefix = "<localleader>c", -- see |chezmoi-template-keymaps|
      icon = nil,                -- glyph for the which-key group
    },
    encryption = {
      enabled = false,           -- opt-in; delegates to chezmoi decrypt/encrypt
      exclude = {},              -- lua patterns of *.age paths to skip
    },
  })
<
A plain string `picker = "telescope"` is shorthand for
`picker = { backend = "telescope" }`.
                                            *chezmoi-template-indent-directives*
format.indent_directives rewrites the interior padding of column-0 `{{-`
whole-line directives so template nesting depth reads as indentation
(1 space + 2 per level): >

  {{- range $name, $spec := .packages.apps }}
  {{-   $roles := get $spec "role" }}
  {{-   if $ok }}
  {{-     $via := get $spec "via" }}
  {{-   end }}
  {{- end }}
<
Directives with leading indentation (embedded in code layout) keep their
single space.

                                                  *chezmoi-template-encryption*
encryption (opt-in) transparently decrypts managed *.age / *.asc files on read
and re-encrypts on write via `chezmoi decrypt` / `chezmoi encrypt`: identities,
recipients, tool choice (age/rage/builtin, even gpg) come from chezmoi's own
encryption config. Decrypted content never touches disk (no swap/undo file).
encryption.exclude lua patterns leave matching paths as plain binary.

4. COMMANDS                                         *chezmoi-template-commands*

                                                                     *:Chezmoi*
:Chezmoi {sub}        Run subcommand {sub}. The subcommand name tab-completes.
                      A leading bang (`:Chezmoi! {sub}`) is passed through to
                      the subcommand.

                                                             *:Chezmoi-apply*
:Chezmoi apply        Apply the current buffer's deploy target.
:Chezmoi! apply       Apply all targets.

                      chezmoi's own source state — `.chezmoi.<fmt>.tmpl`,
                      `.chezmoiignore`, `.chezmoidata/`, `.chezmoiscripts/`,
                      `.chezmoitemplates/` — has no deploy target, so there is
                      nothing to apply. Writing one of those files reports any
                      warning chezmoi has about the current state instead, such
                      as the config template no longer matching the generated
                      config. Such a warning describes standing state rather
                      than the write that surfaced it, so each distinct one is
                      reported once instead of on every save. Use
                      `:Chezmoi! apply` to deploy the effect of such an edit, or
                      `chezmoi init` to regenerate the config.

                                                              *:Chezmoi-diff*
:Chezmoi diff         Diff the current buffer's target in a tab of its own,
                      using Neovim's diff engine: left is the deployed file,
                      right is what chezmoi would deploy (`chezmoi cat`). Both
                      sides are scratch buffers typed as the target filetype,
                      so |]c|, |[c| and syntax highlighting work as usual and
                      the deployed file cannot be edited by accident. `q`
                      closes the tab.

                      Source state that deploys nowhere — `.chezmoitemplates/`,
                      `.chezmoiscripts/`, `.chezmoiignore` — has no file of its
                      own to compare against, and reports that rather than
                      diffing something else. Whole-tree diffs are a git
                      question, answered by git tooling.

                                                            *:Chezmoi-target*
:Chezmoi target       Echo the current buffer's deploy target path.
:Chezmoi! target      Open the deployed file.

                                                            *:Chezmoi-source*
:Chezmoi source       From a deployed managed file, jump to its chezmoi
                      source. (Set redirect = true to do this automatically.)

                                                              *:Chezmoi-edit*
:Chezmoi edit {target}
                      Open the chezmoi source for any deploy target
                      ({target} tab-completes over deployed paths).

                                                           *:Chezmoi-preview*
:Chezmoi preview      Toggle a split with the rendered template
                      (`chezmoi execute-template`), typed as the target
                      filetype. By default the preview re-renders live as you
                      type (debounced by preview.debounce ms); with
                      preview.live = false it re-renders on write only, and
                      renders slower than preview.slow_ms pause live preview
                      to on-write. Invalid template syntax keeps the last
                      valid render, flagged stale in the winbar, until it
                      parses again. The split is vertical by default
                      (preview.split = "horizontal" to change). The preview
                      buffer is named chezmoi-preview://<target> (a
                      dot_zshrc.tmpl previews as .zshrc); `q` (or
                      running the command again) closes it. Refuses
                      non-template buffers. NOTE: templates calling secret
                      managers render real secrets here.

                      Writing a file under `.chezmoitemplates/` also re-renders
                      every open preview, so a source that is a bare
                      `{{ template "…" . }}` passthrough still previews what it
                      pulls in. That happens on write rather than per
                      keystroke: chezmoi reads those files from disk, so an
                      unwritten edit does not exist as far as it is concerned.

                                                              *:Chezmoi-pick*
:Chezmoi pick         File picker over the source directory. Backend from
                      picker.backend; auto-detects loaded pickers
                      (snacks > telescope > fzf-lua > mini.pick), falling
                      back to |vim.ui.select()|. Lazy-loaded pickers may not
                      be detected — set the option explicitly. See
                      |chezmoi-template-picker|.

5. COMPLETION                                     *chezmoi-template-completion*

A blink.cmp source for gotmpl buffers (blink.cmp ≥ 0.13 — per-item kind
icons/highlights). Inside {{ … }} it narrows by cursor position using the
gotmpl treesitter tree (falling back to a line heuristic when the parser is
absent): after a dot (.foo) only data keys (from `chezmoi data`; kind icons
reflect each value's type, docs preview the value); at command position it
also offers template/sprig/chezmoi functions and Go template keywords; inside
string literals nothing. Outside actions it completes block snippets (if,
ifelse, range, rangekv, with, define, block, comment) expanding to full
`{{- … }}…{{- end }}` pairs. Register it in blink.cmp opts: >lua

  sources = {
    default = { "chezmoi", "lsp", "path", "buffer" },
    providers = {
      chezmoi = { name = "chezmoi", module = "chezmoi-template.blink" },
    },
  }
<

6. PICKER                                             *chezmoi-template-picker*

:Chezmoi pick opens a file picker over the source directory. Entries are
built by the plugin (via `git ls-files`, so the source repo's .gitignore is
respected; a plain fs walk for non-git source dirs), identically across
backends:

- Labels show the deployed target name (dot_zshrc.tmpl -> .zshrc); set
  picker.display = "source" for raw source names.
- Chezmoi internals are hidden by default (.git/, .chezmoi.$FORMAT.tmpl,
  .chezmoiversion, .chezmoiroot, .chezmoidata.*) while editable specials stay
  listed (.chezmoiignore, .chezmoiscripts/, .chezmoitemplates/,
  .chezmoiexternal.*). picker.exclude hides additional lua patterns (matched
  against the source-relative path) on top of that list; exclude = false
  shows everything.
- Previews highlight the target language inside the template, same as opening
  the file. Managed encrypted files (*.age, *.asc) preview decrypted when
  encryption.enabled is on, typed as their deployed target.

7. KEYMAPS                                           *chezmoi-template-keymaps*

Two things are set on every chezmoi source buffer, both buffer-local.

'includeexpr' is pointed at the plugin unless the buffer already has one, so
|gf| on the name in `{{ template "part.tmpl" . }}` (or `includeTemplate`) opens
`.chezmoitemplates/part.tmpl`. Those files sit in the source root, nowhere near
the file including them, so plain |gf| never finds them. A name that matches no
such file is left alone and |gf| behaves as usual.

keymaps.enabled (default false) adds bindings under keymaps.prefix (default
`<localleader>c`). No global keys are ever set, so a default prefix cannot
collide with anything outside a source buffer.

    <prefix>p     toggle the preview
    <prefix>a     apply this buffer's target
    <prefix>d     diff
    <prefix>t     open the deployed file
    <prefix>s     jump to the source
    <prefix>e     leave `:Chezmoi edit ` on the cmdline
    <prefix>f     pick a source file

With which-key.nvim loaded the same keys register as a `chezmoi` group, each
with an icon, and the preview entry reports the split's current state
("Preview" or "Close Preview") with a toggle icon to match. keymaps.icon
replaces the group's glyph: >lua

  keymaps = { enabled = true, icon = "" }
<

8. LUA API                                               *chezmoi-template-api*

For statuslines, custom pickers, or scripts.

list()                                            *chezmoi-template.list()*
    Every managed file as a list of { source = <abs>, target = <abs> }
    pairs: >lua
      local files = require("chezmoi-template").list()
<
edit({target})                                    *chezmoi-template.edit()*
    Open the chezmoi source for a deploy target (`~` is expanded); the
    programmatic form of :Chezmoi edit: >lua
      require("chezmoi-template").edit("~/.zshrc")
<
commands.preview_is_open({buf})    *chezmoi-template.commands.preview_is_open()*
    Whether a preview split is open for {buf} (0 or nil = current buffer).
    For a statusline, or a which-key desc/icon function that labels the
    toggle with its state: >lua
      require("chezmoi-template.commands").preview_is_open(0)
<
commands.includeexpr({fname})        *chezmoi-template.commands.includeexpr()*
    Resolve {fname} against `.chezmoitemplates/`, returning it unchanged when
    it names no file there. Set as 'includeexpr' on managed buffers; call it
    directly only to reproduce that wiring elsewhere.

icons.attach()                            *chezmoi-template.icons.attach()*
    Wrap MiniIcons.get() so chezmoi source names resolve to their deployed
    targets. Runs automatically; call it explicitly from a lazy-loaded
    mini.icons `config` if icons don't resolve: >lua
      require("chezmoi-template.icons").attach()
<
icons.get({path})                            *chezmoi-template.icons.get()*
    Return the target's `glyph, hl` for a chezmoi source path, or nil for
    non-chezmoi paths. For statusline/bufferline components: >lua
      local icon, hl =
        require("chezmoi-template.icons").get(vim.api.nvim_buf_get_name(0))
<

9. SECRETS                                           *chezmoi-template-secrets*

What the plugin does by itself:

- Decrypted buffers never persist plaintext: 'swapfile' and 'undofile' are
  disabled, and writes go straight through `chezmoi encrypt` (no plaintext
  temp file).
- Completion docs hide values of data keys matching completion.mask
  (default: secret, token, passw, key, api) — the key still completes, the
  value shows masked.

What to know:

- :Chezmoi preview and diagnostics run `chezmoi execute-template` on the
  buffer — templates calling secret managers (onepassword, vault, pass, …)
  render real secrets into the preview split, and may be slow or fail
  without auth. Don't screen-share the preview of a secrets template.
- cloak.nvim composes well for masking secrets in decrypted buffers — its
  file_patterns match the buffer name, which keeps its encrypted suffix:
  add "*.age"/"*.asc" (or specific names like "*.json.age") to the cloak
  patterns.
